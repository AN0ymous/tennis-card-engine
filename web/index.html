Add your eBay credentials to start scanning

The engine talks to eBay with your own free developer keys. They stay on this machine — the browser never sees them.

  1. Get free API credentials at developer.ebay.com/my/keys.
  2. Create a file called .env next to server.py containing EBAY_CLIENT_ID=… and EBAY_CLIENT_SECRET=…
  3. Restart the server: python server.py

Method and process

How the engine decides

From the serial rule to where the results land, in six parts: what counts as a match, how each listing is filtered, who is licensed, how it runs on a schedule, where results go, and what it deliberately leaves out.

Part 1 of 6

What counts as a match

Four things have to be true at once. Miss any one and the listing is dropped, with the reason written to the activity log.

001/250
First of the run — keep
250/250
Last of the run — keep
1/1
True 1/1, both bookends — keep
1/0
Listed “-1/0”; the minus can't be shown — keep
042/250
Middle of the run — drop
001/750
Run is 500 or more — drop
1 of 2000
Printed on every card in the run, not a serial — drop

A serial is read from the listing's own fields, never invented from them: the checklist number printed in a card's design is not a serial, and a “1 of 2000” run statement is printed identically on every card.

Part 2 of 6

How a listing is filtered

Each of the queries runs through the same seven stages, in order.

  1. Search eBay

    One search per set, newest listings first, against category 212 (Sports Trading Cards) on EBAY_US, fixed-price and auction, up to 1000 listings each.

  2. Identify the player

    Scanning every player, the name is read from the listing's own Player/Athlete field. Narrowed to a roster, every word of the name has to appear in the title, so a Federer search can't hand back a Nadal card.

  3. Pull the full listing

    Titles lie. The engine fetches the item's own specifics — manufacturer, set, print run, card number — and judges those. Details are asked for twenty listings at a time, several requests at once, so a scan costs eBay a fraction of the calls it used to and finishes in seconds. A listing judged on an earlier run is never fetched again.

  4. Turn away cards somebody made themselves

    A custom carries a real maker in its Manufacturer field — one drawn over a Topps design still says Topps — and is nearly always called a 1/1, because only one exists. So neither the allow-list nor the serial rule stops it. Words like custom, aceo, hand drawn and sketch do, matched as whole words against the title and the set. This also turns away licensed artist sketch cards, which read the same in a title.

  5. Check the manufacturer allow-list

    Anything outside the table below is rejected. Panini and Topps also have to name the right set, since those two print far more than tennis. A set name generic enough to appear in a seller's prose — royalty, say — counts only from eBay's own Set field, or from a title that names the maker with it.

  6. Drop known novelty sellers

    Manufacturer strings and sellers confirmed during manual review to be unlicensed custom cards are rejected outright.

  7. Test the serial

    Print run under the ceiling, and the card number is either 1 or the print run itself. Everything else is somebody else's card.

Part 3 of 6

Matched against the listing's own manufacturer field, not the title. Some sets are skipped even when the maker is allowed.

Part 4 of 6

Running it on a schedule

The scan runs itself on GitHub once a day, with nothing of yours left switched on. Everything below is optional — ways to run the same engine on your own machine instead.

On GitHub, daily

scan.yml runs the engine every morning, then commits the results and republishes this page. Press Run a scan above to start one now rather than waiting.

What a scan does

GitHub queues the job, the engine searches and judges, then the site is rebuilt from the new results — the bar above follows those phases. Two to four minutes end to end, most of it the queue and the rebuild rather than the scan.

Or on your own machine

Windows Task Scheduler → new task:

Action:    python.exe
Arguments: tennis_card_engine.py

On macOS or Linux, crontab -e:

0 7 * * * cd /path/to/folder && \
  /usr/bin/python3 tennis_card_engine.py \
  >> cron.log 2>&1
Part 5 of 6

Where the results go

FileHolds
tennis_cards_verified.xlsxEvery qualifying card found, one row each, with a live link to the listing. Nothing is ever removed from it.
new_matches.jsonJust the most recent run's finds — what the Matches panel shows and what the digest email sends.
board.jsonThe recent cards this page puts on the board. Rules added later are applied here, so a card the engine would no longer keep drops off the page while its spreadsheet row stays.
status.jsonActive, sold or ended for every recorded listing, so a saved card can be filtered without a server.
config.jsonThe settings this page reads — the sets, the ceiling, the allow-list — and the time of the last scan.
seen_items.jsonItem IDs already judged, so the same listing is never fetched from eBay twice. Deleting it makes the next scan pay for everything again.
engine_run.logEvery accepted and rejected listing, with the reason for each rejection. Stays on the machine that ran the scan.

On the scheduled run these land in the repository's results/ folder and are published with the page, which is where this site reads them from.

Part 6 of 6

What this doesn't cover

Fanatics Collect and Alt.xyz have no public search API and render their listings in the browser, so monitoring them would mean fragile scraping against their terms of service. This engine deliberately covers eBay only — check those two by hand.

Your eBay credentials are never sent to the browser. Running locally they are read from the environment or the .env file beside the server; on the scheduled run they are GitHub secrets, used only by the scan itself.

Listing data and prices come from eBay and are shown as returned. Always confirm the card on the listing page before buying.
